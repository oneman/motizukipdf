13Run it yourself自分で動かす

Every toolkit box in this guide is live output, regenerated when the PDF is built. To reproduce it:

Commands 
make -C src                                           # build the C library, CLI and TUI
D=docs/initial-theta-data/frey-1-8-9.json             # or frey-1-2400-2401, frey-2-6436341-6436343, curve-11a1

src/iut pipeline --theta-json $D                      # stages 0–7; stage 5 is this guide
src/iut run RepresentMultiradially --theta-json $D    # Thm 3.11: (a)(b)(c), Ind1–Ind3
src/iut run EstimateLogVolume      --theta-json $D    # Cor 3.12 as numbered steps
src/iut run ChainAndSteps          --theta-json $D    # [EssLgc] §3.10 (Stp1)–(Stp8)
src/iut run StepEstimate           --theta-json $D    # [Alien] §3.7 (1est)–(12est)
src/iut run Fuzzify                --theta-json $D    # engulfing, (ExtInd1/2)
src/iut run ClassifyRadial                            # radial environments
src/iut tui --theta-json $D                           # the ncurses TUI: walk the lattice

(cd scripts/multiradial && npm ci) && node scripts/multiradial/build.js   # rebuild this PDF

The web app (scripts/serve.sh, then open htdocs/) has a Pipeline view that runs the same C code compiled to WebAssembly and draws each stage, with an “exact Θ-data (JSON)” option that loads the four examples. The Lean port (cd lean && lake build) proves, among other things, that (Ind1) on packet \(j\) has order \((j+1)!\) (card_Ind1), the closed form of the procession-normalized upper end used in §9.2 (thetaUpperBound_eq), and that \(C_\Theta \ge -1\) is equivalent to the bracket of Theorem 1.10 being non-negative (CTheta_ge_neg_one_iff).
